
# Singletons

1. [[Overlay]]
	Extends Control
	- Global UI necessities: Health Bar, throbber, etc.
	- Mainly for displaying stuff, input is self-contained within MenuScene
	- The different modes are toggled using a state machine setup
	
2. [[Audio]]
	- Plays music and one-shot sounds
		- Looping sounds are attached to relevant objects instead
	- Also manages bus layout (not that important)

3. [[SceneControl]]
	Extends Node
	- Manages the switch between the MenuScene and GameScene
	
	
4. [[SaveGame]]
	Extends Object (Node functionality not required)
	- Contains information to be carried between scenes
	- Also handles saving and loading

# Main Scenes

4. [[MenuScene]]
	Extends Control
	- The menu from which the game is launched and settings are adjusted
	- One of the two "Main Scenes"
	- Contains a Main Menu, File Select, Level Select, Options Menu

5. [[GameScene]]
	Extends Node2D
	- The other main scene
	- Responsible for managing the game part of the software
	- Loads, starts, ends levels, updates the game state
	- Also keeps track of Node pools to easily load/unload objects en masse

# Game objects

## Level
1. [[Level]]
	Extends Node2D
	- Contains the screens of one level
	- Data about next level and completion rewards

2. [[Room]]
	Extends Node2D
	- Three TileMapLayers:
		- Background (not solid, static)
		- Foreground (solid, static)
		- Dynamic (solid, dynamic)
	- Also contains a PlayerSpawn Node

3. [[Player Spawn]]
	Extends Sprite2D (used to display marker)

4. [[Spawn Point]]
	Extends Sprite2D (see above)
	- Resource: SpawnedScene

5. [[Spawned Scene]]
	Extends Resource
	- Texture: preview marker in the editor
	- PackedScene: scene to spawn when screen is initialized

## Enemy

- Every enemy needs:
	- Collision
	- A Sprite
	- A [[BehaviorDriver]]
	- [[Death handler|A way to die]]
	- The behavior to influence the way to die

- Optionally they may also have:
	- A [[Health pool]]
	- Movement
	- A [[Player Detector]]
	- A Projectile Spawner
	

1. [[Architecture/Enemy/Hierarchy.canvas|BaseEnemy]]
	Extends CharacterBody
	- AnimatedSprite
	- DeathHandler
	- BehaviorDriver
	- Hurtbox
	- (Collisions are defined on a per enemy basis and as such no CollisionShape exists on the base scene)

# Player

- The player needs:
	- A [[Carry handler]]
	- A [[Movement state machine]]
	- The two interact somehow (the current action influences the player's movement ability)
	- A [[Health Pool]]
	- Collision Detection (both physical and for [[Hitbox & Hurtbox|contact damage]])
	- A [[Carry handler|way to place bombs]]
	- A [[Player script|way to die]] (the GameScene needs to recognize this)


1. [[Architecture/Player/Hierarchy.canvas|Player]]
	Extends CharacterBody
	- RemoteTransform: for bomb carrying
	- AnimatedSprite
	- [[Movement state machine]] (State machine on Charbody)
		- Player states: standing, walking, knockback, throwing, disabled
	- [[Carry handler]] (script on RTransform)
		- spawn attach and throw bombs
		- changes sprite animations
		- changes movement speed during walk action

2. Bomb
	Extends CharacterBody
	- Timer (fuse)
	- AnimatedSprite
	- [[Projectile Spawner]] (for explosion)

	- Needs to know if it's being thrown

3. Explosion
	Extends Area
	- Timer
	- Sprite
	- CollisionShape

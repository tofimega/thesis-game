## Zoom
- Zoom in: the specific needs and functions of a system
- Zoom out: how systems fit together, in both time and space 

- Always consider *both* of these

## Code
- Modularity: short scripts
- Flexibility: Few dependencies, loose coupling -> easy testing
- Scalability: Easily modifiable, extensible

## Systems
- List systems -> todo list
- Order them in the order of implementation
	- Resolve dependencies
	- Make each feature testable in isolation

- Build a hierarchy tree/graph
	- Which systems communicate with each other and how?
	- Which systems control others?

- Think about how the systems are connected:
	1. List key features of a system
	2. Think about the system from a data perspective
		1. What data does it need?
		2. What data does it produce?
	3. Identify communication lines
		1. What other systems does it interact with?
		2. What data does it need from a particular systems?
		3. Which systems need its data?
		4. Place system into the existing architecture
	4. List "pain points" / possible problems

- Godot specific decisions
	- Nodes, Resources or RefCounted?
		- If a feature produces or requires large amounts of data, Resources are preferred
		- If you need scene tree functionality, use Nodes
		- RefCounted is useful for smaller subsystems
